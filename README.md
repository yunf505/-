# 跨境物流单证核验 · 本地演示

本仓库的演示链路是：浏览器上传同票 PDF → 本地 Python 读取可复制文字并生成契约 A JSON → A 校验器检查字段结构 → B `compare.py` 生成差异与合规提示 → 网页核实并导出 HTML 报告。

## 启动

Windows 上双击 `启动演示.cmd`。所需的两个纯 Python 库已放在 `vendor/`，无需现场联网安装。也可以手动运行：

```powershell
python app.py
```

浏览器打开 `http://127.0.0.1:8765/`。**请通过这个地址访问，直接双击 HTML 文件不能调用本地 Python。** 服务仅绑定本机 `127.0.0.1`，按 `Ctrl+C` 停止。

## 四份上传样例

在网页的“上传单证”页下载 `demo_docs/` 中的报关单、提单、商业发票、装箱单四份 PDF，分别选择对应类型，再点“开始抽取并比对”。四份文件属于同一票完全虚构的货物；商业发票的毛重和净重与其余单证不同，用于展示异常。可以只选其中两类，但四类齐全最能展示完整流程。

这些 PDF 的文字可复制。若需要重新生成，安装 `reportlab` 后运行 `python scripts/generate_demo_pdfs.py`。上传文件在内存中读取，契约 A JSON 仅写入系统临时目录供 B 引擎处理，请求完成后自动清理；核实记录只在当前页面保留，需留档时导出 HTML 报告。

## 模块来源与边界

| 目录或文件 | 用途 |
| --- | --- |
| `modules/line1/` | A 交接包中的契约、规程、校验器和 skill。11 份真实件抽取结果与含实弹记录的交接文档不纳入本次推送。 |
| `modules/line2/` | B v0.2 代码包，包含 `compare.py`、`rules.py`、`verify.py`、契约 B 和自造 JSON 夹具。原代码未改动。 |
| `extract_local.py` | 本次新增的确定性文本 PDF 提取器，输出契约 A。它不是 A 的 agent 视觉抽取流程。 |
| `app.py` | 本次新增的本地 HTTP 服务，上传、校验、调用 B 引擎并返回结果。 |
| `vendor/` | 本地运行所需的 pypdf 6.10.0 与 python-dotenv 1.2.2；各自许可证随目录保留。 |
| `C-页面设计稿.html` | 企业用户页面；可查看完整提取字段、分级差异、不可比项、合规提示，记录人工结论并导出报告。 |

首版只支持按四种单证类型选择、带可复制文字且使用演示标签版式的 PDF。扫描件、图片、任意企业版式和 OCR 尚未接入；对于不认识的标签会报错或将字段标为缺失。不要把演示效果解读为对真实业务单证的抽取准确率。

`raw_pdf/` 与 `赛题二测试资料（精简）/` 是仓库既有资料，不是本次自造上传样例。其中包含真实单证，`raw_pdf/` 还包含套 D；本地演示请使用 `demo_docs/`。现有仓库已跟踪部分真实 PDF，新增的 `.gitignore` 不会自动移除既有 Git 历史，后续对外发布前需单独处理资料范围。

## 自检

在各自模块目录运行 `python verify.py`（B）和 `python scripts/check_consistency.py`（A）。网页端到端可用四份样例实际上传；返回结果应包含四份契约 A 字段、同一票的差异卡片和可导出的核验报告。
