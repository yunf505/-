## 2. 已实测通过的三个数（可直接引用）

```text
E6 提单号模糊匹配：MAEUSZHVJM535 vs MAEU92ZKVJM35 → ratio = 0.769
票01 金额：|26762.00-26762.40| = 0.40，tol = max(1.00, 0.005×26762.4) = 133.81 → 绿
票02 金额：|84200-89000| = 4800，tol = 445.00，相对偏差 5.39% → 红
```

> **编号相似度阈值建议取 0.70**（不是 0.75）。E6 实测 0.769，取 0.75 只差 0.019 的余量，太窄；
> 取 0.70 既保住该案例，又不会把真不同的编号放过。

## 3. 不清楚 / 未定的地方（已标出，不要硬猜）

以下是规格里**确实没定死**的点。处理方式已给出建议，实现时按建议走，**并在答辩稿的"已知限制"里如实写出来**——这比硬编一个答案安全得多。

### ① `raw_span` 的格式不一致 ⚠ 最需要确认

- A 的 `示例-packing_list-虚构.json` 用的是**字符串**：`"raw_span": "PACKING LIST No.: ..."`
- A 实际产出的 11 份 JSON 用的是**对象**：`"raw_span": {"page": 1, "text": "..."}`

**本套数据采用对象形式**（B 需要 page 号做证据展示）。
**引擎必须两种都能吃**：

```python
def span_text(raw):
    return raw if isinstance(raw, str) else (raw or {}).get("text", "")
```
**已向 A 提请确认统一格式。**

### ② 日期链缺字段（影响 T5）

A 给的日期链判据需要「出口日 / 装船日 / 进口日 / 申报日 / 汇总日」五个日期。
但契约A v1.1 里：

- `customs_declaration` 只有 `declaration_date`（栏7 Entry Date）一个
- `bill_of_lading` **没有任何日期字段**（`vessel_voyage` 只拆船名航次）
- 装箱单有 `packing_date`，发票有 `invoice_date`

**所以完整日期链目前实现不了。** 本套票05 用 `packing_date` vs `declaration_date` 做**近似**验证（制单日晚于申报日 = 矛盾）。
**装船日属 A 已开的 v0.5 提案通道，待补字段后再完整实现。**

### ③ 「单证缺失」的判定基准未定义（影响 T6）

契约里没有任何地方说"一票应该有哪些单证"。本套采用的**线2 提案**：

```python
EXPECTED = {"customs_declaration", "commercial_invoice", "packing_list", "bill_of_lading"}
missing = EXPECTED - {d.doc_type for d in group}
# 缺失即报黄（level=yellow, category="missing_doc"）
```

票05 按此应报 1 条黄（缺 commercial_invoice）。
**这是提案不是定论，需与 A/D 确认**——实务里散货可能确实没有提单，一刀切会误报。

### ④ 「HS 疑似错归」只能做一半（影响 T4）

A 的 T4 写了两种情形：

- ✅ **跨证 HS 不一致** → 纯规则可做，票04 就是
- ❌ **HS 与品名语义不符**（如品名写"笔记本"却归到汽车零件）→ 需要语义理解，
  而分工表明确禁止 LLM 参与判定

**只做前半段**，后半段写进已知限制。这是守纪律，不是偷工。

### ⑤ 装箱单/发票没有 `hs_code` 字段

两个新 doc_type 的 16/17 字段里都没有 HS。
所以跨证 HS 比对**只能走 报关单 ↔ 提单**（提单从 `goods_description` 内嵌抽取），票04 即此路径。

### ⑥ 必填项具体是哪几个未写明

A 说"装箱单必填 3 项、发票必填 6 项"，但 schema 没标哪些是必填。
**本套数据把所有字段都填了非空值**（除刻意埋的 null），因此**不会触发任何必填校验失败**，安全。
若后续要测"必填缺失被闸门拦下"，需先向 A 拿到必填清单。

### ⑦ 箱号来源的降级链

- 发票 / 装箱单：有 `container_no` 字段，直接取
- 提单：**无该字段**，从 `goods_description` 的 `raw_span` 正则捞 ISO 6346：
  ```python
  re.findall(r"\b[A-Z]{4}\d{7}\b", goods_description + " " + span_text(raw_span))
  ```
  本套票01/票04 的提单描述里都写了 `Ctnr SYNU……`，可被捞到。
- 三条都对不上时降级到 `bl_no`，再不行降级到「发票号 + 金额/件数/重量三元组」，**不得放弃该票**（E5）。
