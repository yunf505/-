# 抽取规程 · v0.3

> **本文件是线1的核心固定资产。** 任何 agent（人或 AI）执行单证抽取时，必须完整遵循本规程。
> 修改本文件视同修改代码：改动须记入 `docs/决策记录.md` 并提升版本号。
> 版本历史：v0.1（2026-10-05 初版）→ v0.2（预留号，未发布）→ **v0.3（2026-10-06 边界与跨执行者一致性收紧：据实弹测试+3 独立执行者一致性实验修订，见 docs/已知限制.md）**

## 1. 你的任务

输入一份单证文件（PDF 或图片，报关单/提单），你输出**契约A格式**的结构化字段 JSON。

**你只做提取，不做判定。** 差异比对、风险分级、合规判断属于线2，即使你在单证上发现了"可疑之处"，也**不得**在输出中做任何评价——最多写入 `parse_meta.warnings` 里的客观描述（如"金额栏有涂改痕迹"），不下结论。

## 2. 铁律（违反任意一条即输出作废）

1. **禁止猜测填充**：看不清、看不懂、栏位空缺、被涂黑/脱敏遮盖 → `value: null`，`confidence: 0`。宁可空，不可编。
2. **每个非空字段必须给 `raw_span`**：原文依据（页码+原文片段），供下游解释与展示。
3. **归一化由你完成**（规则见第 5 节），下游拿到的一律是归一化后的值。
4. **数字照抄**：原文里的数字必须原样转写，不得改、不得估；单位换算只在归一化层做并保留 `raw_span` 原文。
5. **先分类再抽取**：先判断 `doc_type`（customs_declaration / bill_of_lading），按对应字段表抽取。
6. **输出前自检**：你的输出必须能通过 `src/validate.py` 校验，否则打回重做。

## 3. 输出 JSON 骨架

```json
{
  "schema_version": "0.1-draft",
  "prompt_version": "v0.3",
  "doc_type": "customs_declaration 或 bill_of_lading",
  "source_file": "输入文件名（含相对路径）；一文件多票时加 #p页码 后缀",
  "engine": "执行引擎自报：agent 名称/模型标识，如 'qwenwork-agent'（必填，供可复现性记录）",
  "fields": {
    "<字段名>": {
      "value": "<归一化后的值；缺失为 null>",
      "confidence": 0.95,
      "raw_span": { "page": 1, "text": "原文片段" },
      "normalized": true
    }
  },
  "parse_meta": {
    "ocr_used": false,
    "pages": 1,
    "warnings": []
  }
}
```

`fields` 中必须包含该 `doc_type` 字段表的**全部字段**——缺失字段的条目也要有，`value: null`。

## 4. 字段表

### 4.1 报关单 customs_declaration

| 字段 | 指什么 | 必填 | 归一化要求 |
|---|---|---|---|
| declaration_no | 海关编号/预录入编号 | ✅ | 去空格；**编号必须跨页/跨单证互证**（见 §5.7） |
| domestic_consignor | 境内收发货人（**仅名称行，不含街道地址/邮编**） | ✅ | 去多余空白 |
| overseas_consignee | 境外收发货人（仅名称行，不含地址） | 可空 | 同上 |
| trading_country | 贸易国(地区) | ✅ | ISO 两位码 + 中文名，如 "US / 美国" |
| port_of_dispatch | 启运港 | 可空 | 地名保留原文；**为 CBP 港口代码时照抄代码并置 normalized=false** |
| port_of_destination | 指运港/入境口岸 | 可空 | 同上 |
| transport_mode | 运输方式 | ✅ | 枚举：sea / air / rail / road / multimodal |
| transaction_mode | 成交方式 | ✅ | 枚举：FOB / CIF / CFR / EXW / 其他 |
| hs_code | 商品编号 | ✅ | 去点号去空格，10 位数字；不足位保留原样并写 warnings；**多行明细全列为数组** |
| goods_name | 商品名称及规格型号 | ✅ | **string（不数组化）**；多行明细用"; "连接，顺序与 hs_code 数组逐项对应 |
| quantity | 数量及单位 | ✅ | 数组 [{value: float, unit: str}]，法定第一/第二数量分列 |
| total_value | 总价+币制 | ✅ | {amount: float, currency: "ISO4217 三位码"} |
| gross_weight_kg | 毛重 | ✅ | float，统一 KG；**仅分行动值时分行加总，raw_span 注明"分行加总"并写 warning**（见 §5.8） |
| net_weight_kg | 净重 | 可空 | float，统一 KG；法定计量单位非 KG（如 L/CARTO/NO）时置 null，禁止换算猜测 |
| packages | 件数 | ✅ | int |
| declaration_date | 申报日期 | ✅ | YYYY-MM-DD；**取栏规则见 §5.9（先 Summary Date，后 Entry Date）** |

### 4.2 提单 bill_of_lading

| 字段 | 指什么 | 必填 | 归一化要求 |
|---|---|---|---|
| bl_no | 提单号 | ✅ | 去多余空白；编号互证规则见 §5.7 |
| shipper | 发货人（仅名称行，不含地址） | ✅ | 去多余空白，大小写保留原文 |
| consignee | 收货人（仅名称行，不含地址） | ✅ | 同上；"TO ORDER" 等指示抬头照抄 |
| notify_party | 通知人（仅名称行，不含地址） | 可空 | 同上 |
| vessel_voyage | 船名航次 | 可空 | 拆 {vessel, voyage} 两字段 |
| port_of_loading | 装货港 | ✅ | 保留原文 |
| port_of_discharge | 卸货港 | ✅ | 同上 |
| packages_and_weight | 件数与毛重 | ✅ | {packages: int, gross_weight_kg: float, unit: str} |
| goods_description | 货物描述 | ✅ | 保留原文；若含 HTS 号另抽 hs_code，唛头另抽 marks |

> 注 1：hs_code 多行明细"全列为数组"、多页续页"合并为一条记录"、置信度"分字段独立"已定稿（见 docs/定稿确认单.md）。
> 注 2：提单侧 hs_code / marks 字段不在 field_specs.bill_of_lading 中，按口径表"另抽取到 hs_code/marks"可带上，属"冻结后加字段"待全队确认；建议 v0.4 提案正式加入 issue_date / place_of_delivery。

## 5. 归一化与判定规则

| 类型 | 规则 | 失败时 |
|---|---|---|
| 日期 | 一律 `YYYY-MM-DD` | 无法解析则保留原串、`normalized: false`、写入 warnings |
| 金额 | 去千分位与货币符号转 float；币种单列 ISO4217 | 同上 |
| 重量 | 统一 KG：MT×1000、LB×0.45359237 | 同上 |
| 数量 | 数值 float 与单位字符串分列，不混排 | 同上 |
| HS 编码 | 去点号与空格，10 位为主 | 不足 10 位保留原样并写 warnings |
| 人名/企业名 | 去多余空白与标点差异，大小写保留原文；**只取名称行** | 比对容差由线2 决定，你只管忠实转写 |

### 5.7 编号字段互证规则（declaration_no / bl_no / 提单号/箱号）
- 同票编号通常出现在多处（7501 表头、3461 表头、页眉传真头、装箱单/发票引用）。**读出后必须找第二处互证**。
- 各处读数一致 → confidence 正常（0.95/0.70 档）。
- 各处不一致 → 取**最高分辨率**读数为准，confidence 降到 0.5，并在 warnings 里列出全部候选读数（含出处），交人工复核。禁止凭偏好选一个就交差。

### 5.8 毛重聚合规则（gross_weight_kg）
- 单证有整票毛重栏（如提单 Gross Weight、7501 第 30 栏为整票值时）→ 直接取。
- 仅有分行动值 → 分行加总，`raw_span` 注明"分行加总(各行值)"，并写 warning。
- 跨单证（如装箱单）合计值只能作互证参考，**不得替代本单证自身数值**；参考值不一致时写 warning。

### 5.9 申报日期取栏规则（declaration_date）
- 7501：**优先取 Summary Date**；该栏空白时取 Entry Date；raw_span 必须注明实际取自哪个栏位。签署日期（Signature Date）不取，但与所取日期相差大时写 warning。
- 提单：取 Date of Issue（契约正式字段待加，暂记 warnings）。
- 中国报关单：取"申报日期"栏，无则取"进口日期"并注明。

### 5.10 形近字符复核规则
B/8、D/Q、O/0、I/1/l、S/5、Z/2 在扫描件上极易混淆。凡编号/代码/金额字段中出现上述字符且字形存疑时：**对该区域做局部放大（提高渲染 dpi）复核**；仍无法定论 → 按 §5.7 处理（保留最可能读数+降级+warning 列候选）。

### 5.11 多单证同文件/同页规则
- 一个 PDF 含多票或多类单证 → **一票一记录**，`source_file` 加 `#p页码(PageID)` 后缀；同票的 3461/装箱单/发票在 warnings 注明"另行抽取"。
- 一页内合排多单证（如发票页内嵌装箱列）→ 按该页的**主单证类型**抽取；合排引入的他人字段不得混入；页内两单证数据并存时以各单证自身栏位为准，禁止跨单证拼值。

## 6. 保密件处理须知（红线）
含 **CONFIDENTIAL / BUSINESS PROPRIETARY 标记、SWIFT/银行账号、个人联系方式**的文件（如同票套D）：
1. **只本地处理**：渲染/读取/输出全部在本机完成，禁止调用任何云端 OCR/API 上传该文件内容；
2. 抽取输出 JSON 仅落 `out/`（不入 git、不上平台）；
3. JSON 内照抄敏感串（SWIFT/账号）是允许的（本地中间产物），但**任何演示、报告、截图、上传物**引用前必须先脱敏（责任：线4 D）；
4. 与普通件混批处理时，在 `parse_meta.warnings` 标注 "confidential_source"。

## 7. 置信度口径

| 情形 | confidence |
|---|---|
| 文本层/印刷体清晰直读命中 | 0.95 |
| 扫描件清晰、但含轻度噪声 | 0.70 |
| 需要跨栏位推断/排版复杂/字迹模糊/编号互证不一致 | 0.50 |
| 缺失 | 0 |

## 9. 执行流程

1. 读入文件（**PDF 用 pymupdf 渲染 ≥150dpi PNG 再视觉读取**；Read 直读法院件会误报加密；缩略图 ≤50dpi 只做页级定位不得抽字段）；
2. 判断 `doc_type`（无法判断 → 整单输出全部 null，warnings 说明原因）；
3. 逐字段抽取 → 归一化 → 标注 confidence 与 raw_span（编号/代码字段执行 §5.7/§5.10 复核）；
4. 一票多页则合并记录（续页行项目并入数组，raw_span 标注实际页码）；
5. 自查铁律 1-5；
6. 运行 `python src/validate.py <你的输出.json>`，**FAIL 则修正后重跑，直到 0 error**；
7. 交付输出 JSON（真实件的输出只落 `out/`，不入 git；保密件执行 §6）。
