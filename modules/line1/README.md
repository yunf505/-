# 线1 · 单证信息抽取(Information Extraction)

主责:A ｜ 状态:开发中 ｜ 建立:2026-10-01

## 这个模块做什么
输入单证文件(PDF/图片)→ 输出**契约A**格式的结构化字段 JSON。
只做"提取",不做"判定"——差异比对属于线2(B),本模块不得越界写比对逻辑。

## 目录约定
| 目录 | 放什么 | 进 git |
|---|---|---|
| `schema/` | 契约A(schema.json)+ 字段口径表(含归一化规则) | ✅ |
| `prompts/` | 抽取提示词 + few-shot 片段(脱敏后) | ✅ |
| `src/` | 解析管线代码 | ✅ |
| `eval/` | 评测脚本 + 临时标准答案(**不含真实单证**) | ✅ 脚本 / ❌ 数据 |
| `out/` | 抽取输出 JSON | ❌ 忽略 |
| `HANDOFF-B/` | 交付给 B 的交接包 | ❌ 忽略(含真实数据输出) |
| `docs/` | 已知限制、决策记录 | ✅ |

## 三条红线(违反即返工)
1. **真实单证与其抽取输出永不进 git、永不上平台**——M4 上传只用自造或脱敏样例;
2. **归一化在本模块完成**(日期/金额/单位/HS),否则线2 比对无法对齐;
3. **每个字段必须带 `confidence` 与 `raw_span`**(原文依据),供 B 解释与 C 展示。

### 隐私红线 · 机制说明
"真实单证永不入库"不是口头约定,由 `.gitignore` 机制强制:`data/`(本地放真实件)、`out/`、`HANDOFF-B/`、`eval/gt_raw/`、`eval/gt_draft/` 及全部图片/PDF 扩展名(`*.pdf` `*.png` `*.jpg` 等)默认排除。
任何新目录在 `git add` 前先想一下:**这里面会不会间接出现真实单证内容或其抽取结果?** 会,则先加 ignore 规则。few-shot 示例入 `prompts/` 前必须脱敏(替换真实企业名/税号/货值)。
